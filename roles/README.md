# 角色体系与编号规范

## 角色编号规则
所有 AI 会话使用 `R + 两位数字 + 岗位名称` 命名（如 `R01-架构师`）。编号一旦分配，项目周期内保持稳定。每一编号对应一个独立 AI 会话/子代理。

## 标准角色池
以下角色按项目需要选用，不是每个项目都需要全部角色。

| 编号 | 岗位名称 | 核心职责 | 是否写代码 |
|------|---------|---------|-----------|

> PM 需要全局视图（自动化模式注入 skill）时，逐个查看对应角色文件的「Skill 绑定」小节。
> **优先级**：项目约束（AGENTS.md / 任务卡 / docs/）**高于** skill 工作方法。skill 是"怎么做得好"的增强，不是"做什么"的权威；冲突时以项目约束为准并在回报中标注。加载规则见 AGENTS.md 启动流程第二步。

**绑定规则**（全局，各角色文件不再重复）：
1. 各角色文件绑定为角色级默认；PM 建卡时可通过任务卡「默认 skill」字段覆盖（指定额外 skill 或写「无」取消）
2. 设计类 skill 不覆盖已冻结的 `docs/design-system.md`
3. 单角色默认绑定 skill ≤ 2 个；`ai-model-*` 系列按技术栈只选其一
4. 绑定 skill 必须存在于当前宿主可用 skill 清单（DSH 以本会话 available_skills 为准）；不存在 → 按 AGENTS.md「加载失败必报」处理，不静默跳过

## 会话命名与编号
自动化模式：PM 拉起子代理时注入 `roles/templates/worker-init.md`，子代理命名**固定为 `R0X-岗位名`（编号+角色名，不带任务简述后缀）**——因为复用采用常驻模式，一个角色在其生命周期内处理多张卡，命名需保持稳定。
手工 fallback：用户在侧边栏新建同名对话，粘贴 worker-init.md 为第一条消息。
角色按 AGENTS.md 启动流程自动完成初始化。
示例：`R99-PM`、`R02-后端工程师`。
> 高频规则唯一权威映射见 `docs/规则权威索引.md`。

## 常驻与并行实例规则

- **默认**：每个角色只保留一个常驻子代理（`R0X-岗位名`），该角色的多张卡按依赖/优先级顺序用 `send_message` 续派，不重复拉起、不关闭。
- **同一角色并行实例（例外）**：仅当同一角色有 ≥2 张卡、顺序执行会造成可感知的关键路径阻塞，且通过 `docs/自动化协作协议.md` §3.6 四条耦合检查时，PM 才可为该角色额外拉起**临时并行实例**。临时实例必须显式命名（如 `R02-后端工程师#TC-007`）并在 `docs/thread-routing.md` 标记为“临时并行实例”；该卡验收合并后临时实例回收/废弃，常驻实例保持唯一。
- 拿不准是否值得并行时，默认串行。
