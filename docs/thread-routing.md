# 对话路由表

> PM 维护此表，每唤起/操作一个角色子代理时更新。
> 本表中的"对话标识" = **运行时句柄，不作为 SSOT 持久化**（DSH 用 `list_agents` 实时查询 subagentId，Codex 用侧边栏对话名称）。agent id 绑定当前 PM 会话、重启即失效——本表持久化的稳定事实是「角色 → 当前任务卡」映射与角色状态，运行时句柄由 PM 临时记录、重启后丢弃并重新查询。
> **任务卡状态/角色/工作目录**以 `task-cards/*.md` 文件头 front-matter 为唯一权威，下方「当前任务卡索引（自动生成）」由 `scripts/generate-status.ps1` 生成，**勿手改**——本表只维护角色状态（active/idle/working/blocked/completed）与对话标识。

## 活跃对话

> **登记规则**：本表只登记**已激活**的角色（PM 按项目类型推荐、用户确认后的角色组合）。角色池共 12 个（R99 + R01~R11，见 `roles/README.md`），未激活角色**不预登记**——需要时由 PM 按需拉起并补登本表，避免误读为"全角色默认激活"。
> **唤起即登记（硬约束）**：PM 每唤起一个角色子代理，必须**立即**在本表补登该角色的角色状态并标 `working`（对话标识为运行时句柄，用 `list_agents` 查询、不落盘）；未登记不得派发。本表是 PM 的编排记录，**子代理不得用本表反推自己的身份**——角色身份以 PM 注入的初始化消息为准（见 AGENTS.md 启动流程第一步）。
> **临时并行实例**：同一角色额外拉起的临时并行实例以 `R0X-岗位名#TC-XXX` 登记在「角色名称」列，并在「角色状态」注明“临时并行实例”；该卡验收合并后移除该行，常驻实例保持唯一。

## 角色状态说明

> 本表状态为**角色状态**（未唤起/active/idle/working/blocked/completed）。任务卡与回报使用独立的**任务状态**（todo/in_progress/done/accepted/merged/partial/blocked，存于 front-matter）。两套状态维度不同、互不替代：角色状态描述"对话是否在干活"，任务状态描述"任务卡走到哪一步"。`patrol.ps1` 按维度分别校验，不混用。

> **编排模型：唤起后常驻，不关闭**（角色模型见 `roles/README.md`，宿主差异见 `docs/dsh-capabilities.md` / `docs/codex-capabilities.md`）。子代理唤起后保持常驻，后续卡用 `send_message`（DSH）/ `send_input`（Codex）续派，验收后**不关闭**；子代理生命周期随父（PM）会话存续，父重启后旧 agent id 失效、重新唤起。`idle` 表示角色常驻待命、等待下一张卡。

| 状态 | 含义 |
|------|------|
| 未唤起 | 已激活但尚未拉起子代理（初始化时按推荐组合唤起，唤起后转入 idle/working） |
| active | 正常运行中（当前 PM 线程） |
| idle | 常驻待命，等待新任务卡（唤起后常驻模型的常态状态） |
| working | 正在执行任务卡 |
| blocked | 被阻塞，需要 PM 介入 |
| completed | 已完成所有任务，常驻待命（父 agent 重启前保持，需要时 send_message 续派新卡） |
