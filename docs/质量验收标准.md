# 质量验收标准

> 由 R99-PM 维护。定义 PM 验收和 R03 测试必须覆盖的质量维度。
> 此文档解决一个核心问题：**PM 写任务卡验收标准时可能遗漏非功能性质量维度，导致「功能正常但质量不达标」的代码被验收通过。**

---

## 一、质量四层模型

```
Layer 1: 功能验收 ──→ 它做对了吗？
    ↓
Layer 2: 技术验收 ──→ 它做得规范吗？
    ↓
Layer 3: 用户体验验收 ──→ 它好用吗？
    ↓
Layer 4: 生产环境验收 ──→ 它能上线吗？
```

每一层有**必查项**（必须覆盖，不可跳过）和**条件项**（满足条件时覆盖）。PM 写任务卡验收标准时逐层对照，R03 测试时确保覆盖。

### 1.1 验收证据分层（AI 自证 vs 外部证据）

> 解决"AI 自证式验收"问题：验收项分两类，PM/R03 必须区分，防止"打勾 = 通过"的自我确认循环。

| 类型 | 定义 | 可采信方式 | 典型项 |
|------|------|-----------|--------|
| AI 可验证 | 代码/文档层面的静态事实 | 回报自述 + PM 抽查代码/文件即可确认 | 分层合规（T1b）、错误码规范、测试文件存在且可运行（F8 部分）、契约一致性、无明文密钥（T4 部分） |
| 必须外部证据 | 需要真实环境/工具运行结果 | 回报必须附证据；**无证据 = 该项未通过**，不得勾选 | T3、T7、U5、P2、P3、P8、P9、P10、P11、F8 测试结果 |

> **例外（两阶段验收）**：P2/P3/P9/P10 默认责任主体为用户·PM/R06，按 §1.2 证据责任矩阵声明「待外部提供」后**不阻塞任务验收**（登记上线验收清单），不适用本表「无证据 = 未通过」的强制逻辑；其余外部证据项（T3/T7/U5/P8/P11/F8）无证据即驳回。

**证据最低形式**：
- 部署类（P2/P3）：公网可访问 URL + 访问验证记录
- 性能类（U5/P8/T7）：Lighthouse / 压测报告（含复现命令）
- 浏览器类（T3）：浏览器矩阵自动化运行日志或三端截图
- 监控/日志类（P9/P10）：监控平台查询链接、告警规则配置截图
- CI 类（F8/P11）：CI 运行链接或本地运行完整输出

### 1.2 证据责任矩阵（谁产出证据）

> 解决"外部证据死锁"：明确每项证据的**责任主体**、**可接受形式**、**生成时机**。子代理只对其"可生成"的证据负责；其余证据由 CI / R03 / 用户·PM 在正确时机提供，**不阻塞任务验收**，转入上线验收清单。

#### 责任主体定义

| 主体 | 定义 | 证据生成环境 |
|------|------|-------------|
| 角色（子代理） | 任务执行者 | 自身工作区 / 沙箱，本地命令可完成 |
| R03 | QA 工程师 | 测试环境（可含本地） |
| CI/流水线 | 自动化流水线 | 项目 CI 平台（如 GitHub Actions） |
| 用户·PM | 需部署权限 / 账号 / 人工环境的主体 | 公网、云控制台、监控平台 |

#### 子代理沙箱能力边界（默认假设，以实际环境为准）

| 能力 | 沙箱默认状态 | 说明 |
|------|------------|------|
| 本地命令运行（测试/构建/lint/类型检查） | ✅ 可生成 | 完整命令 + 输出 + 退出码 |
| 本地服务启动 + localhost 探测 | ✅ 可生成 | curl / 脚本探测结果 |
| 本地截图 | ⚠️ 视环境 | 有浏览器工具（如 Playwright）时可生成 |
| 本地性能测量（Lighthouse / k6 对 localhost） | ⚠️ 视环境 | 可安装工具时可生成 |
| 公网部署 URL | ❌ 不可 | 无部署权限 |
| 生产 / 第三方凭证配置 | ❌ 不可 | 无账号 / 权限 |
| 监控 / 日志平台数据 | ❌ 不可 | 无账号 |
| 真实浏览器矩阵（含 Firefox/Safari） | ❌ 默认不可 | 沙箱通常仅 Chromium |
| CI 平台运行链接 | ❌ 默认不可 | 取决于项目是否有 CI 及触发权限 |

> 沙箱能力以实际环境为准：若子代理实际可生成某项"默认不可"的证据（如环境具备完整浏览器矩阵），按可生成处理；"默认可"但环境缺失时，按本节约硬约束走替代路径或上报 PM。

#### 证据项责任矩阵（外部证据项全表）

| 证据项 | 默认责任主体 | 可接受证据形式 | 替代 / 降级路径 | 生成时机 |
|--------|------------|--------------|----------------|---------|
| F8 测试通过 | 角色（含 R03） | CI 链接 或 本地运行完整输出 | 无 CI → 本地完整输出（含退出码）；有 CI → CI 链接 | 任务验收 |
| T3 浏览器兼容性 | R03（或 CI） | 浏览器矩阵运行日志 / 三端截图 | 沙箱无多浏览器 → Playwright 自动化 + 单浏览器截图并标注覆盖范围；仍不可行 → 上报 PM，按豁免或转「待外部提供」（发布前由用户/CI 补测） | 任务验收 / 上线前 |
| T7 API 性能 | R03 | 压测报告（含复现命令） | 无压测工具 → 本地 autocannon/k6 对 localhost 的 P95，标注"本地环境"；生产 P95 由 CI/用户在上线后验证 | 任务验收（本地）/ 上线后（生产） |
| U5 首屏性能 | R03 | Lighthouse 报告 | 沙箱可安装 Lighthouse → 对本地服务生成；否则转「待外部提供」，由用户在发布前对 staging/生产生成 | 任务验收 / 上线前 |
| P8 性能指标 | R03 | Lighthouse 报告 | 同 U5；Light 规模默认豁免 | 上线前 |
| P11 CI/CD 通过 | CI 平台 | CI 运行链接 | 项目无 CI → 本地完整构建 + 测试输出替代，标注"无 CI，本地验证" | 任务验收 |
| P2 后端部署 | 用户·PM（或 R06/CI） | 公网可访问 URL + 访问验证记录 | 无部署环境 → 登记「待外部提供」，上线验收时补 | 上线验收 |
| P3 第三方服务就绪 | 用户·PM | 控制台配置状态截图 | 同 P2 | 上线验收 |
| P9 错误监控 | R06 / 用户·PM | 监控平台查询链接 / 告警规则配置截图 | 无账号 → 登记「待外部提供」；Light 规模默认豁免 | 上线验收 |
| P10 日志采集 | R06 / 用户·PM | 日志平台查询链接 / 截图 | 同 P9 | 上线验收 |

#### 证据状态机

| 状态 | 含义 | 标记人 | 对验收的影响 |
|------|------|--------|------------|
| 已附 | 证据已随回报提供且可复核 | 角色 / R03 | 满足验收 |
| 待外部提供 | 该证据责任主体非角色（用户·PM / CI / R06），需在指定时机提供 | 角色在回报中声明（限责任矩阵中允许的项） | 不阻塞任务验收，PM 登记上线验收清单 |
| 不适用 | 本任务不涉及该证据项 | 角色（写明理由） | 满足验收 |
| 豁免 | 初始化时按规模级别裁剪 | PM | 满足验收（引用豁免记录） |

#### 两阶段验收

| 阶段 | 触发 | 证据要求 |
|------|------|---------|
| **任务验收**（单卡） | 角色回报 → PM 验收 | 只要求责任主体为「角色 / R03 / CI」且状态为「已附」的证据；「待外部提供」项不阻塞，PM 登记到上线验收清单（`docs/project-status.md` 或上线前检查） |
| **上线验收**（发布前） | PM 宣布上线前 | PM / 用户 / CI 补齐上线验收清单中所有「待外部提供」项，对照 Layer 4 执行——即 R99-PM「上线前检查」的职责范围 |

#### 硬约束（修订版）

1. 责任主体为「角色 / R03 / CI」的证据项（F8、T3、T7、U5、P8、P11 默认）：回报未附证据 → **驳回**，不接受"已验证"自述
2. 责任主体为「用户·PM / R06」的证据项（P2、P3、P9、P10 默认）：回报必须声明「待外部提供」+ 预计提供时机；未声明 → 驳回；已声明 → **不阻塞任务验收**，登记上线验收清单
3. 「待外部提供」仅限责任矩阵中默认责任主体非角色的证据项；角色责任项（F8/T3/T7/U5/P8/P11）不得以"待外部提供"绕过——环境确实不可行时上报 PM，由 PM 决定豁免或转交
4. 证据必须可复核：命令类含完整命令 + 输出 + 退出码；截图类含生成时间 / 环境标识；不可复核 → 视为未附
5. 豁免项必须引用初始化时记录的豁免理由（`docs/project-status.md`），否则驳回
6. 纯文档 / 纯配置任务不涉及外部证据项时，在回报「4.2 外部证据清单」填写"不适用（理由）"

## 二、Layer 1：功能验收

> **核心问题**：代码做的是不是任务卡要求的事？

### 必查项

| # | 检查项 | 如何验证 | 谁负责 |
|---|--------|---------|--------|
| F1 | 验收标准逐条通过 | 对照任务卡验收标准逐条打勾 | PM |
| F2 | 正向流程正常 | 用户主流程走通，无阻断 | PM / R03 |
| F3 | 边界条件覆盖 | 空输入、超长输入、特殊字符、数值边界 | R03 |
| F4 | 异常/错误处理 | 网络失败、超时、权限不足、资源不存在时的表现 | R03 |
| F5 | 与原型/PRD 一致性 | 逐页对照设计规范和 PRD | PM |
| F8 | 自动化测试覆盖 | 涉及前端页面或后端逻辑的任务，核心链路有自动化测试且全部通过（前端组件测试 / 后端单测）；测试命令可运行、测试文件随代码入库 | 测试文件存在与命令可运行：AI 可验证；测试通过结果：【外部证据】CI 链接或本地运行完整输出 |

### 条件项

| # | 检查项 | 触发条件 | 如何验证 |
|---|--------|---------|---------|
| F6 | 权限控制 | 任务涉及鉴权/角色 | 未登录/无权限用户无法访问受保护资源 |
| F7 | 数据一致性 | 涉及数据库写入 | 写入后读取一致；事务回滚正确 |

## 三、Layer 2：技术验收

> **核心问题**：代码是否符合技术规范和行业标准？

### 必查项

| # | 检查项 | 如何验证 | 谁负责 |
|---|--------|---------|--------|
| T1 | 框架/组件库合规 | 未出现裸写 HTML/CSS 替代组件库、未裸写 HTTP Server/拼接 SQL | PM |
| T1b | 分层合规 | 代码遵循 `architecture.md` §3 的四层模型——Controller 无业务逻辑、Domain 不依赖框架、Infrastructure 封装外部调用 | PM |
| T2 | 代码复用 | 未重复造轮子；同类功能是否提取为公共组件/工具函数 | PM |
| T3 | 浏览器兼容性 | 【外部证据】Chrome/Edge/Firefox/Safari 最新两个主版本均正常（浏览器矩阵运行日志或三端截图） | R03 |
| T4 | 安全基线 | 无明文密码、无 XSS 注入点、敏感接口有鉴权 | R03 |

### 条件项

| # | 检查项 | 触发条件 | 如何验证 |
|---|--------|---------|---------|
| T5 | SEO | 项目有面向公网的前端页面 | 关键页面有 title/description；语义化 HTML；图片有 alt；核心内容非 JS 动态注入 |
| T6 | 无障碍（a11y） | 项目面向 C 端用户或政府/教育客户 | 可键盘导航；表单有 label；色彩对比度达标；屏幕阅读器可读取关键内容 |
| T7 | API 性能 | 涉及后端 API | 【外部证据】核心接口 P95 响应时间 < 500ms（内部）/ < 200ms（网关）（压测报告） | R03 |
| T8 | 数据库查询效率 | 涉及数据库操作 | 无 N+1 查询；核心查询有索引覆盖 |
| T9 | 开源方案评估 | 涉及第三方功能（按项目实际涉及） | 是否检索过 GitHub 现有方案并记录评估结论 |

## 四、Layer 3：用户体验验收

> **核心问题**：用户用起来是否流畅、直观？

### 必查项

| # | 检查项 | 如何验证 | 谁负责 |
|---|--------|---------|--------|
| U1 | 响应式/移动端适配 | 手机/平板/桌面三端布局不错乱、内容不溢出 | R03 |
| U2 | 加载状态 | 所有异步操作有 loading 指示器或骨架屏，无白屏等待 | PM / R03 |
| U3 | 空状态 | 列表为空、搜索无结果、数据为空时有提示，非空白页 | PM |
| U4 | 交互反馈 | 按钮点击有反馈（hover/active/disabled 状态正确）；操作成功/失败有 toast 提示 | PM |
| U5 | 首屏加载性能 | 【外部证据】Lighthouse Performance ≥ 80；首屏 FCP < 2s；LCP < 2.5s（Lighthouse 报告） | R03 |

### 条件项

| # | 检查项 | 触发条件 | 如何验证 |
|---|--------|---------|---------|
| U6 | 表单体验 | 任务涉及表单 | 实时校验、错误提示在输入框旁边、提交按钮防重复点击 |
| U7 | 动画/过渡 | 设计规范要求动画 | 页面切换/组件显隐有过渡，不突兀 |
| U8 | 文案质量 | 有面向用户的中文文案 | 无错别字、无技术术语泄露给用户、语气一致 |

## 六、使用方式

### 6.1 PM 写任务卡时

PM 对照四层模型，在任务卡的"验收标准"区域确保覆盖了对应层级的必查项：

> **边界/异常覆盖建议（WARN，不阻断派发）**：每张任务卡的验收标准建议至少包含 1 条边界条件（对应 F3）+ 1 条异常处理（对应 F4）。`scripts/validate-task-card.ps1` 以关键词启发式仅做提示（缺失 → WARN，不再阻断派发）；语义完整性把关依赖 R03 验收标准评审（第二道防线，见 `PM-操作指南.md` §3.0）。`light: true` 轻量卡与纯文档/纯配置类任务卡（front-matter `workdir=主工作区` 且 `workdir_note` 填写理由）自动跳过该提示。
> **外部证据约束**：验收标准引用【外部证据】项（T3/T7/U5/P2/P3/P8-P11/F8）时，必须写明证据形式（如"附 Lighthouse 报告""附部署 URL"）；责任主体默认按 §1.2 证据责任矩阵，PM 可显式调整（如把 T3 指定为"CI 提供"）；引用用户·PM 责任项（P2/P3/P9/P10）时须注明"该证据上线验收时由用户/PM 提供，不阻塞本卡验收"。未写明 → PM 驳回。

```markdown
## 验收标准

### 功能验收
- [ ] 用户点击「提交」后，数据正确写入数据库
- [ ] 输入为空时，「提交」按钮置灰不可点击
- [ ] 网络失败时显示错误提示，不白屏

### 技术验收
- [ ] 使用组件库的表单组件，不手写表单
- [ ] Chrome/Edge/Firefox 均可正常使用

### 用户体验验收
- [ ] 提交过程中按钮显示 loading 状态
- [ ] 操作成功显示 toast 提示
- [ ] 手机端布局正常

### 生产环境验收
- [ ] 无 mock 数据残留
```

> **验收标准评审（第二道防线）**：大卡（预计复杂度=高，或涉及契约/schema/冻结产出物/外部证据项，或多角色协作）的验收标准在派发前须经 R03 评审（可测性/完整性/外部证据可行性/契约一致性，见 `PM-操作指南.md` §3.0），评审通过后 PM 将 `acceptance_reviewed_by: R03` 写入任务卡 front-matter。light 卡 / 小卡 / 纯文档卡可豁免，PM 写明 `不适用（理由）`。

> **粒度原则**：不是每张任务卡都要逐层全填。小任务卡（修一个文案）只需功能验收。中等任务卡（新增一个页面）覆盖功能+技术+体验。大任务卡（完整模块）四层全覆。

### 6.2 PM 最终验收时

PM 读取回报后，对照四层模型的必查项逐条确认：

```markdown
## 最终质量核查

- [ ] F1-F5 + F8 全部通过
- [ ] T1/T1b/T2/T3/T4 全部通过
- [ ] U1-U5 全部通过
- [ ] P1-P7 全部通过
```

任何一条未通过 → 不通过验收。**验收标准全部打勾 ≠ 质量通过。**

> **外部证据核查**：标记【外部证据】的项，PM 对照 §1.2 责任矩阵逐条核对回报「4.2 外部证据清单」：
> - 角色/R03/CI 责任项（F8/T3/T7/U5/P8/P11）缺证据或不可复现 → 驳回，不接受"已验证"自述
> - 用户·PM 责任项（P2/P3/P9/P10）声明「待外部提供」→ 登记上线验收清单，不阻塞本卡
> - 豁免项须核对初始化豁免记录（`docs/project-status.md`）

### 6.3 R03 测试时

R03 参照此文档，确保测试覆盖了任务卡对应的质量层级。在回报开头声明：

```
本次覆盖层级：功能（F3/F4/F6）+ 技术（T3/T4）+ 体验（U1/U2/U5）+ 生产（P4/P6）

涉及【外部证据】项时，R03 按 §1.2 责任矩阵确认自己是否为责任主体：
- 是（T3/T7/U5/P8 默认）→ 在回报「4.2 外部证据清单」逐条附证据（URL/日志/报告/截图/CI 链接）；证据缺失的项不得勾选通过
- 否（P2/P3/P9/P10 默认责任主体为用户·PM/R06）→ 在回报中声明「待外部提供」+ 预计提供时机，不勾选该项为"已通过"，由 PM 登记上线验收清单
```
