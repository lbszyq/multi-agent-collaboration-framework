# PM 项目初始化清单

> 由 R99-PM 在初始化新项目时使用。解决「复制框架后第一步做什么」的空缺：创建 Git 基线、选择规模级别、激活角色组合、裁剪质量标准、初始化状态文档。
> 与 `docs/项目规模适配指南.md`、`docs/thread-routing.md`、`docs/质量验收标准.md` 配套使用。
> 存量项目（已有代码 / git 历史 / 部分文档）走 `docs/存量项目接入清单.md`，本清单仅适用于空项目（从零开始）。

---

## 一、前置：框架文件已就位

- [ ] `AGENTS.md` / `roles/` / `docs/` / `scripts/` / `task-cards/template.md` / `reports/template.md` 已复制到新项目根目录（AGENTS.md 直接复制，不重新生成）
- [ ] 已 `git init` 并完成首个提交

---

## 二、Git 基线（必须先做，跳过会破坏分支策略）

- [ ] 创建 `develop` 分支：`git branch develop` —— 框架默认 `develop` 为集成分支，但模板仓库本身只有 `main`，**初始化时必须手动创建**
- [ ] **主工作区切换到 `develop`：`git checkout develop`** —— 主工作区归 PM 专用，默认检出集成分支 `develop`；PM 后续的 `docs/`、`task-cards/`、`reports/` 维护（建卡/回填/改状态/归档）全部落在 `develop` 上。**若停留在 `main`，新建任务卡不会进入 `develop`/feature 分支，feature worktree 中找不到任务卡、`merge-card.ps1` 合并必然失败（详见 `docs/git-workflow.md` §4.1）**
- [ ] 确认合并权限：`main` 只接受 `develop` 合并（由 PM 或 R06 批准）；feature 分支一律从最新 `develop` 创建
- [ ] 在 `docs/project-status.md` 记录：`规模级别：[Light / Standard / Enterprise]`

> 未创建 `develop` 时，`patrol.ps1` 会提示「未检测到 develop 分支，跳过未合并分支检查」——这是初始化遗漏的信号，不是正常状态。

## 三、规模级别选择

| 级别 | 适用场景 | 角色数 | 关键裁剪 |
|------|---------|--------|---------|
| Light | 个人项目 / 原型验证 / 单次 demo | 3-5 | 不需要 ADR、`contracts/`、设计系统文档、正式 CR；代码类任务卡一律独立 Worktree（主工作区归 PM 专用；light 卡按 `docs/轻量任务通道.md` 在主工作区执行） |
| Light-AI | 求职/实践级 Agent 项目（以六大标准为验收目标） | 4-6 | Light + Agent 最小集（`architecture.md` §2 运行时能力/上下文工程/可观测性/人机协同 + `ai-evaluation-template.md`） |
| Standard | 中型商业项目 / 团队协作 | 6-9 | 全套文档（当前框架完整版） |
| Enterprise | 大型商业项目 / 多平台 / 合规 | 10-12 | Standard + 全面 ADR、独立契约文件、安全合规文档 |

判定问题（详见 `docs/项目规模适配指南.md`）：开发周期 / 平台数 / 是否有 AI 模块 / 是否需要 CI/CD / 团队规模 / 是否有合规要求。

## 四、角色组合推荐与激活

| 项目类型 | 推荐角色组合 |
|---------|-------------|
| Web 全栈 | R99 + R10 + R11 + R01 + R02 + R04 + R03（+R06 如有 CI/CD） |
| 移动端 | R99 + R10 + R11 + R01 + R02 + R07/R08 + R03 |
| AI·ML | R99 + R10 + R11 + R01 + R09 + R02 + R04 + R03（+R05 如数据量大） |
| 数据平台 | R99 + R10 + R01 + R05 + R02 + R06 + R03 |

- [ ] 向用户展示推荐组合并确认（人类决策节点，不自动放行）
- [ ] 按 `docs/thread-routing.md` 登记规则，**只登记已激活角色**，未激活角色不预登记
- [ ] 角色池完整清单见 `roles/README.md`（R01~R11 + R99），可按需扩展（用 `roles/templates/role-definition.md`）

## 五、裁剪质量标准

- [ ] Light / Light-AI / Standard 项目在 `docs/project-status.md` 记录豁免的【外部证据】必查项（如 Light 豁免 T3 浏览器矩阵、P8 Lighthouse、P9 Sentry），并写明理由——豁免记录是回报「4.2 证据状态=豁免」的引用依据（见 `质量验收标准.md` §1.2）
- [ ] 任务卡验收标准按 `docs/质量验收标准.md` §6.1 粒度原则填写：小卡只需功能验收，中等卡功能+技术+体验，大卡四层全覆
- [ ] 纯文档/纯配置任务卡在 front-matter `workdir_note` 字段写明理由（机器据此自动跳过 F3/F4 关键词提示，无需在正文额外写明——见 `docs/质量验收标准.md` §6.1）

## 七、首次巡检验证

- [ ] 运行 `.\scripts\patrol.ps1`（注意：需 PowerShell 7 / pwsh，Windows PowerShell 5.1 无法解析）
- [ ] 确认 `[结果] PASS`，无 FAIL 项

## 八、常见错误

| 错误 | 后果 | 避免方法 |
|------|------|---------|
| 忘记创建 develop | feature 分支从 main 创建，破坏分支策略 | 初始化时执行 `git branch develop` |
| 主工作区停留在 main | PM 建卡/改状态只进 main，develop 与 main 分叉；feature worktree 中找不到任务卡、merge-card 必然失败 | 初始化时 `git checkout develop`，主工作区默认检出 develop（见上方 Git 基线节） |
| context-brief.md 保持占位 | patrol FAIL「认知恢复」，新对话无法可靠恢复 | 初始化时填真实内容 |
| 全部 12 角色登记到路由表 | 误读为全角色默认激活，初始化负担翻倍 | 只登记已激活角色 |
| 用 Windows PowerShell 5.1 跑脚本 | 中文乱码 / 解析失败 | 统一用 pwsh 运行 |
