## Backlog（候选需求池）

> **职责**：记录「想法已提出、尚未决定做 / 未排期」的候选事项，防止丢失（对话记录执行完即失效，不是事实存储）；排期时由 PM 转成任务卡。
> **与任务卡 / CR 的分工**：任务卡 = 已决定要执行；CR（`docs/变更管理流程.md`）= 已决定要改的变更；Backlog = 未决定 / 未排期。
> **维护**：PM 手工维护（非自动生成区）。状态流转：`候选` → `已排期(TC-XXX)` → `已实现` / `已放弃`；排期转卡后更新状态并关联任务卡号。
> **清理**：已实现 / 已放弃的条目保留一行并标注状态（可追溯），不删除。
